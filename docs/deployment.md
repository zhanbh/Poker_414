# 私房扑克内测部署

## 前置条件

准备一台能被内测玩家访问的 Node.js 主机，安装 Node.js 22+，开放一个应用端口。当前版本包含 414 和德州扑克两种玩法，不需要数据库；应用可以直接提供 HTTP，也可以放在 Nginx 等 HTTPS 反向代理后面。

## 构建与启动

```powershell
npm ci
$env:INVITE_CODE = "只发给内测玩家的固定码"
$env:HOST = "0.0.0.0"
$env:PORT = "3000"
npm run build
npm start
```

也可以复制 `.env.example` 为 `.env`，再由进程管理器注入这些环境变量。必须提供 `INVITE_CODE`；缺失时服务会拒绝启动，不会回退到公开访问。

服务提供：

- `GET /health`：返回 `{ "ok": true, "roomOccupied": false|true }`。
- `/`：同一 Node 进程提供 `dist/client` 的静态页面。
- Socket.IO：使用与页面相同的 HTTP 地址承载网页版登录、入房和牌局命令。
- `/414-ws`：供微信小程序使用的 WebSocket 兼容通道。

## 内测操作

1. 内测负责人把访问地址和邀请码分别发给参与者。
2. 参与者在入口选择玩法，输入唯一昵称；第一个入房者成为房主。
3. 414 需要四名玩家入座后开始；德州扑克至少两名有筹码玩家即可开始，最多八个玩家位，牌局中加入者等待下一局。
4. 需要暂停时直接关闭页面或保持无操作；系统只显示暂离，不会自动替玩家出牌。
5. 结束后由房主结束房间；服务重启也会清空内存房间、牌局和房间聊天。

## 安全边界

开发环境可以直接使用普通 HTTP，但邀请码和会话令牌不应通过公网明文传输。生产环境应让 Nginx 或其他反向代理负责 HTTPS/WSS，Node 应用端口只允许内网或本机访问；不要公开发布邀请码。正式化前至少应轮换邀请码、增加正式身份认证，并重新评估会话、日志和房间持久化策略。
