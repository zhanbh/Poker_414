# 414 内测部署

## 前置条件

准备一台能被四位玩家访问的 Node.js 主机，安装 Node.js 22+，开放一个 HTTP 端口。当前版本不需要数据库或反向代理。

## 构建与启动

```powershell
npm ci
$env:INVITE_CODE = "只发给内测玩家的固定码"
$env:HOST = "0.0.0.0"
$env:PORT = "3000"
npm run build
npm start
```

也可以复制 `.env.example` 为 `.env`，再由进程管理器注入这些环境变量。必须提供 `INVITE_CODE`；缺失时服务会拒绝启动，不会回退到公开访问。

服务提供：

- `GET /health`：返回 `{ "ok": true, "roomOccupied": false|true }`。
- `/`：同一 Node 进程提供 `dist/client` 的静态页面。
- Socket.IO：使用与页面相同的 HTTP 地址承载登录、入房和牌局命令。

## 内测操作

1. 内测负责人把 HTTP 地址和邀请码分别发给四位玩家。
2. 四位玩家输入唯一昵称；第一个入房者成为房主。
3. 四人到齐后房主开始游戏，按页面提示处理首牌权、立棍/反立和正常出牌。
4. 需要暂停时直接关闭页面或保持无操作；系统只显示暂离，不会自动替玩家过牌。
5. 结束后由房主结束房间；服务重启也会清空内存房间和当前牌局。

## 安全边界

本内测明确使用普通 HTTP，因此邀请码会明文传输，会话令牌也只适合受控网络。不要公开发布邀请码或把地址当作正式服务。正式化前至少应切换 HTTPS、轮换邀请码、增加正式身份认证，并重新评估会话、日志和房间持久化策略。
